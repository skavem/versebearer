# build

## Purpose
Wails3 build pipeline. Shared tasks plus one subdirectory per target OS, each holding that platform's Taskfile and its assets: Windows NSIS installer and VERSIONINFO, Linux nfpm packaging + AppImage builder, macOS bundle plists. Driven by the root `Taskfile.yml`, which `includes:` these files under the names `common`, `windows`, `darwin`, `linux`.

## Key Files
| File | Description |
|------|-------------|
| `Taskfile.yml` | Shared tasks: `go:mod:tidy`, `install:frontend:deps`, `build:frontend`, `generate:bindings`, `generate:icons`, `dev:frontend`, the three `reciever` tasks, `update:build-assets` |
| `config.yml` | Wails3 build config: app metadata (still default "My Company / My Product" — needs updating), `dev_mode` watcher rules, file associations |
| `appicon.png` | Source icon, converted to `windows/icon.ico` + `darwin/icons.icns` by `wails3 generate icons` |
| `windows/Taskfile.yml` | Windows `build`, `generate:syso`, `create:nsis:installer`, `run` |
| `windows/info.json` | VERSIONINFO data consumed by `wails3 generate syso` |
| `windows/wails.exe.manifest` | Windows executable manifest |
| `windows/nsis/` | NSIS installer script (`project.nsi`), Wails NSIS helpers (`wails_tools.nsh`), bundled MS Edge WebView2 bootstrapper |
| `darwin/Taskfile.yml` | macOS build, universal binary, `.app` bundle |
| `darwin/Info.plist`, `darwin/Info.dev.plist` | macOS bundle plists |

| `linux/appimage/` | AppImage `build.sh` |

## For AI Agents

### Working In This Directory
- This layout is the Wails beta.5 one, adopted 2026-08-08. `wails3 update build-assets` regenerates only the *generated* files (`info.json`, manifests, plists, nfpm config, `wails_tools.nsh`) from `config.yml` — it never writes Taskfiles, so edits there survive. It is still a one-way sync for what it does touch.
- Three deviations from the upstream templates are deliberate and would be lost in a naive re-sync: the `reciever` tasks, `-d ./frontend/src/lib/bindings` on binding generation (upstream defaults to `frontend/bindings`), and `CGO_ENABLED: 1` (upstream defaults to `0`; the SQLite driver is cgo, so `0` does not build).
- `DEV` selects the build mode. `DEV=true` drops the `production` tag so the window proxies the frontend to vite; anything else builds production. The root `Taskfile.yml` defaults it to `"false"`, so `build` and `package` are production unless asked otherwise. See the Dev mode section in `../AGENTS.md`.
- Windows build embeds the manifest + icon via a `.syso` generated by `wails3 generate syso` (sourced from `windows/icon.ico`, `windows/wails.exe.manifest`, `windows/info.json`). The `.syso` is deleted post-build.
- Production build flags on Windows: `-tags production -trimpath -buildvcs=false -ldflags="-w -s -H windowsgui"`. The `windowsgui` linker flag hides the console window — which also means a production binary has nowhere to print stderr. For diagnostics build a one-off without it: `go build -tags production -o bin/versebearer-debug.exe .`
- `run: once` on `go:mod:tidy`, `build:frontend`, `build:reciever` and `generate:bindings` is not cosmetic: several build branches depend on them in parallel, and two `go mod tidy` processes (or a bindings regen racing its own reader) corrupt state intermittently.
- Vite dev port is 9245 by default (root `Taskfile.yml` `VITE_PORT`). Override via env: `WAILS_VITE_PORT=NNN task dev`.
- Binding generation passes `-clean=true`: the output directory is wiped first so files of deleted services don't linger. Safe only because `frontend/src/lib/bindings` is fully generated and gitignored.
- `task test` at the repo root runs `go test ./...`. No Wails/frontend deps needed — tests construct `&DbHandler{}` with a nil app and rely on the `emit()` wrapper's nil-guard.

## Dependencies

### External (build-time)
- `wails3` CLI (bindings, syso, icons, build-assets).
- `task` (go-task).
- `go` toolchain (1.25+ per `go.mod`; required by `wails/v3` ≥ beta.5). Auto-fetched via the toolchain directive if local Go is older.
- `npm` (frontend and reciever).
- Per-OS: NSIS (`makensis`), nfpm, AppImage tools, `lipo` (macOS universal).
